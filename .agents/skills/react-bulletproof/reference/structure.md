# Project structure

```
src/
├── assets/            # fonts, images, animations
├── components/        # shared UI only
│   ├── ui/            # shadcn-managed, never hand-edit, compose around it
│   ├── common/        # generic building blocks (error states, empty states)
│   ├── data-display/  # tables, viewers, cards
│   ├── forms/         # inputs, form wrappers
│   ├── overlays/      # dialogs, drawers, popovers
│   ├── layout/        # shells, sidebars, headers
│   └── providers/     # app-level context providers
├── constants/         # urls, config values, menu items
├── features/<name>/   # most code lives here (see below)
├── hooks/             # generic hooks: use-debounce, use-table-state, ...
├── i18n/              # i18next setup + generated registry
├── integrations/      # third-party client setup (tanstack-query provider)
├── lib/               # custom libraries + core singletons (axios, base-schema)
│   └── <lib>/         # see custom-library.md
├── routes/            # file-based routes (generated route tree, never hand-edit)
├── services/          # app-wide services (permissions, active user)
├── stores/            # Zustand stores: use-<name>-store.ts
├── types/             # shared types: index.ts + <topic>.d.ts
├── utils/             # pure helpers; builders get their own folder
│   ├── payload-builder/{index.ts,payload-builder.ts}
│   └── query-builder/
└── env.ts             # Zod-validated env; the only place reading import.meta.env
test/                  # tests for global code, mirrors src/
```

## Feature module

```
src/features/<feature>/          # e.g. src/features/product/
├── components/   # one component per file, kebab-case: product-table.tsx
├── constants/    # column definitions, static options
├── hooks/        # feature hooks: use-product-form.ts
├── i18n/         # <locale>.json per language, index.ts (typed Translations)
├── schema/       # Zod schemas via createSchemaFactory
├── services/     # plain async fns or use-* query wrappers
├── types/        # index.ts (enums, interfaces) + dto.d.ts (request/response)
├── utils/        # pure feature helpers
└── test/         # <name>.test.ts(x) for this feature
```

Rules:

- Features do not deep-import each other's internals. Import a type or public helper via `@/features/<other>/types`, never a component file chain.
- If two features need the same thing, move it to the shared folder.
- File names are kebab-case. Hooks `use-<thing>.ts`. Stores `use-<thing>-store.ts`. Services named by action: `product-action.ts`, `use-get-product-list.ts`.
- Generated files (route tree, i18n registry) are regenerated by their script, never edited.

## Data flow

```
component ──► hook (useQuery/useMutation) ──► service fn ──► axios instance (lib/axios.ts)
                                                                 │ interceptors: auth header,
                                                                 │ refresh on 401, 503 redirect
```

- Server state: React Query. Client/UI state: Zustand or local hooks.
- No axios in components. No token/cookie handling outside the token store + interceptor.
- Request bodies with conditional fields use `PayloadBuilder` (`createPayload<T>().set().when().build()`), not chains of `if`.
- Forms: react-hook-form + `zodResolver(schema)`; schemas built with `createSchemaFactory(() => shape)` to get `.schema() .partial() .pick() .omit()`.

## Imports

- Always `@/…` across folders. Relative imports only inside one lib/feature subtree (`./websocket-backoff`, `../transport.types`).
- `import type { … }` for type-only imports (`verbatimModuleSyntax` is on).
- Order: external packages, then `@/` imports, then relative; `import type` lines after value imports of the same group.

## tsconfig essentials

`strict`, `noUnusedLocals`, `noUnusedParameters`, `noFallthroughCasesInSwitch`, `noUncheckedSideEffectImports`, `verbatimModuleSyntax`, `moduleResolution: bundler`, `paths: { "@/*": ["./src/*"] }`.
